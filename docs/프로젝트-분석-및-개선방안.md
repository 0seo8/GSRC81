## 전체 프로젝트 구조 분석

### ✅ 잘 구현된 부분

1. **서버/클라이언트 컴포넌트 분리** (지도 페이지, 코스 상세 페이지)
   - `/map` 페이지는 서버 컴포넌트로 데이터를 가져온 뒤 클라이언트에 전달
   - 병렬 데이터 패칭으로 성능 최적화
   - Next.js 15의 장점을 제대로 활용

2. **타입 안정성**
   - TypeScript 사용
   - 대부분의 컴포넌트에 타입 정의

3. **컴포넌트 구조**
   - UI 컴포넌트 분리 (`components/ui/`)
   - 도메인별 컴포넌트 정리 (`components/map/`, `components/admin/`)

### ⚠️ 개선이 필요한 부분

1. **불필요한 클라이언트 컴포넌트**
   - 관리자 페이지들이 `"use client"`로 되어 있음
   - 서버 컴포넌트로 변경 시 초기 로딩 속도 대폭 향상 가능

2. **에러 처리 부족**
   - `alert()` 사용 (UX 저하)
   - 에러 바운더리 미흡
   - 재시도 메커니즘 없음

3. **타입 안정성 부족**
   - `as` 타입 단언이 너무 많음 (특히 GPX 업로드)
   - 런타임 검증 없음

4. **코드 중복**
   - 모바일/데스크톱 레이아웃 중복
   - 데이터 패칭 로직 중복

export async function getAdminStats() {

    supabase.from("courses").select("*", { count: "exact", head: true }),
    supabase.from("course_comments").select("*", { count: "exact", head: true }),

    totalComments: commentCount.count || 0,
    activeUsers: userCount.count || 0  // ✅ 실제 데이터

// 1. Zod로 타입 검증
// lib/validation/gpx-schema.ts
import { z } from 'zod'

export const GPXDataSchema = z.object({
  name: z.string().min(1),
  distance: z.number().positive(),
  startPoint: z.object({
    lat: z.number().min(-90).max(90),
    lng: z.number().min(-180).max(180),
  }),
  coordinates: z.array(
    z.object({
      lat: z.number(),
      lng: z.number(),
      ele: z.number().optional(),
    })
  ).min(2),
})

// 사용
try {
  const validatedGPX = GPXDataSchema.parse(gpxData)  // ✅ 안전한 검증
  // 처리...
} catch (error) {
  if (error instanceof z.ZodError) {
    toast.error("GPX 파일 형식 오류", {
      description: error.errors.map(e => e.message).join(", ")
    })
  }
}

// 2. Server Actions 사용 (Next.js 15)
// app/admin/courses/actions.ts
'use server'

export async function createCourse(formData: FormData, gpxData: unknown) {
  const validated = GPXDataSchema.parse(gpxData)
  const processed = processGPXData(validated)

  await supabase.from("courses").insert([{
    ...extractFormData(formData),
    gpx_data: processed,
  }])

  revalidatePath('/admin/courses')  // 캐시 무효화
  revalidatePath('/map')

  return { success: true }
}

// 3. Toast 사용 (alert 대신)

## 주요 문제점 및 개선 방안

### 1. 과도한 클라이언트 컴포넌트 사용 ⚠️ 심각

**문제:**
- 관리자 페이지들이 모두 `"use client"`
- 서버에서 렌더링 가능한 부분도 클라이언트에서 처리
- 초기 로딩 속도 저하

**영향:**
- 번들 크기 증가
- 초기 렌더링 지연
- SEO 불리

**해결:**
```typescript
// Before ❌
"use client"
export default function AdminPage() {
  const [data, setData] = useState([])
  useEffect(() => {
    fetchData().then(setData)
  }, [])
  return <div>{data.map(...)}</div>
}

// After ✅
export default async function AdminPage() {
  const data = await fetchData()  // 서버에서 가져오기
  return <div>{data.map(...)}</div>
}
```

**우선순위:** 🔴 높음

// lib/validation/gpx.ts
import { z } from 'zod'

export const GPXDataSchema = z.object({
  name: z.string().min(1, "이름은 필수입니다"),
  distance: z.number().positive("거리는 양수여야 합니다"),
  startPoint: z.object({
    lat: z.number().min(-90).max(90),
    lng: z.number().min(-180).max(180),
  }),
  coordinates: z.array(
    z.object({
      lat: z.number(),
      lng: z.number(),
      ele: z.number().optional(),
    })
  ).min(2, "최소 2개의 좌표가 필요합니다"),
})

// app/admin/courses/actions.ts
'use server'

import { toast } from 'sonner'

export async function createCourse(formData: FormData, gpxData: unknown) {
  try {
    // ✅ 안전한 검증
    const validated = GPXDataSchema.parse(gpxData)

    // ✅ 서버에서 안전하게 처리
    const processed = processGPXData(validated)

    await supabase.from("courses").insert([{
      ...extractFormData(formData),
      gpx_data: processed,
    }])

    revalidatePath('/admin/courses')

    return { success: true }
  } catch (error) {
    if (error instanceof z.ZodError) {
      return {
        success: false,
        error: error.errors.map(e => e.message).join(", ")
      }
    }
    throw error
  }
}

    })
  }
